## 2. Цель
Оценить качество публичных информационных функций сайта: доступность страниц, навигацию, отображение контента, ссылки, доступность документов, адаптивность и отображение валидации форм без отправки реальных персональных данных.

## 3. В рамках тестирования
- Отображение главной страницы.
- Навигация в шапке и футере.
- Публичные информационные страницы, на которые ведут ссылки с главной.
- Страница Owner's Manuals и доступность/открытие ссылок на документы.
- Отображение полей формы подписки и клиентская валидация без отправки реальных данных.
- Базовая доступность: клавиатурный фокус, подписи полей, понятные ссылки, альтернативный текст изображений (если доступен для проверки).
- Адаптивность на типовых размерах экрана.
- Smoke-проверки в нескольких браузерах.

## 4. Вне рамок тестирования
- Эксплуатация, сборка, обслуживание и характеристики огнестрельного оружия.
- Боеприпасы и баллистика.
- Покупка, оформление заказов, дилерские поставки и процессы продаж.
- Закрытые/административные разделы, пентест, сканирование уязвимостей и нагрузочное тестирование.
- Отправка реальных заявок и подписок.

## 5. Подход к тестированию
1. Изучить публичные страницы и пользовательские элементы.
2. Подготовить и выполнить ручной чек-лист.
3. Выполнить тест-кейсы и записать фактический результат.
4. Сохранить доказательства воспроизводимых ошибок.
5. Описывать только подтверждённые дефекты.
6. После ручной проверки автоматизировать стабильные read-only сценарии.

## 6. Виды тестирования
- Smoke testing
- Functional UI testing
- Проверка навигации и ссылок
- Compatibility testing
- Responsive UI testing
- Базовая проверка accessibility
- Наблюдение за валидацией форм

## 7. Тестовые данные
Использовать только синтетические неперсональные строки для проверки локальной валидации, если она доступна без отправки формы. Не отправлять форму и не создавать аккаунты.

## 8. Критерии начала
- Сайт доступен публично.
- Браузер и тестовая среда записаны.
- Тест-кейсы и чек-лист просмотрены.

## 9. Критерии завершения
- Для всех запланированных проверок указан статус.
- Для каждого Fail записаны воспроизводимые шаги и доказательства, если их безопасно получить.
- Непроверенная проблема не называется подтверждённым багом.
- Подготовлен краткий итоговый отчёт.

## 10. Риски и ограничения
Сайт может измениться во время тестирования. Сторонние скрипты, региональные ограничения, cookie-настройки и сеть могут влиять на поведение. Формальной спецификации публичных страниц нет, поэтому ожидаемый результат должен основываться на явно наблюдаемом поведении и документированных предположениях.
